## Real data and commands

The screen consumes the existing `PypyControlCenter` props from `App.tsx`. It creates no additional WebSocket and changes no subscriptions or message handling. The SVG makes one abortable, retryable request to the existing `/api/telemetry/topology?grid_name=…` endpoint. Connectivity and generator/load roles come from that API; fixed coordinates are layout positions only. Voltage, breaker state, compromise markers and flow direction come from telemetry. Missing or stale evidence is unavailable, never replaced with runtime fixtures.

The existing callback sends unchanged `grid/attack` START/STOP payloads. The two scenarios are the ones already exposed in the working simulation page: FDIA (target, bias, scale) and breaker manipulation (target, OPEN). The dialog lists assets present in telemetry. It does not offer invented attack types, automatically change the grid, or directly operate breakers through the topology.

Sending a command displays “awaiting confirmation.” Subsequent telemetry must report the selected attack and compromised asset, or confirm attack cessation. A 15-second timeout reports an **unknown/unconfirmed outcome**, not invented backend rejection. Connection loss is explicit. STOP remains available during an unconfirmed launch. STOP does not claim recovery.

Telemetry must have a source timestamp less than 30 seconds old. Model readiness uses timestamped readiness messages, with a 60-second expiry. Threat and trust displays require recent source data. Timeline entries are existing event/alert/recovery-evidence records, with their source timestamps. Historical events can remain visible when the live stream is unavailable.

Stages represent evidence actually received; they do not advance on a timer. Recovery requires an explicitly approved, recent CLOSE following an OPEN initial state, later matching closed-state telemetry, no active attack, matching experiment IDs when supplied, solver convergence, all reported bus voltages within 0.95–1.05 p.u. and no open breakers. OPEN actions, STOP, stale dispatch, unapproved control and a different experiment cannot trigger the success headline. No detection/recovery duration or confidence metric is fabricated.

## Motion, audio and idle behavior

- SVG dashed flow animates only for fresh telemetry with a closed breaker and measured power magnitude above 1 MW. Direction follows its sign; animation speed is illustrative, not a physical velocity measurement.
- Compromised-node halos, evidence-stage pulses and new timeline entries use lightweight CSS. No rendering engine or animation dependency was added. `prefers-reduced-motion: reduce` disables the animation/transition effects.
- Audio starts muted. Unmute creates/resumes a Web Audio context from the user gesture. Quiet, short sine tones mark a newly observed attack, anomaly, or verified recovery; no alarm loops. The context closes on exit. Browser failures produce a visible message.
- After 45 seconds without pointer, keyboard, touch or wheel activity, a clearly labelled presentation-only attract panel rotates messages every eight seconds. It never sends control messages. Interaction immediately exits it, and an open attack dialog prevents activation. Live telemetry freshness rules continue to apply.
- Fullscreen uses the browser API only, with a graceful failure notice.
