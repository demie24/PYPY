# PYPY Grid — Production Deployment Checklist This document serves as the official pre-flight verification and configuration checklist for deploying PYPY Grid V11.9 GA in a high-availability, production-hardened environment. --- ## 1. Network & Firewall Hardening Before bringing the servers online, configure the operating system firewall to block all unauthorized ports. - [ ] Enforce SSH access via non-standard port and key-based authentication only. Password login must be disabled in `/etc/ssh/sshd_config`. - [ ] Enable UFW (Uncomplicated Firewall) on Ubuntu/Debian nodes. - [ ] Allow incoming traffic on port 80 (HTTP) and port 443 (HTTPS) only. - [ ] Allow incoming traffic on port 1883/8883 (MQTT TLS) if external hardware clients are connecting directly. - [ ] Verify that internal container ports (5432 for PostgreSQL, 6379 for Redis, 8000 for Gateway API) are NOT exposed on public interfaces. Check `netstat -tuln` to confirm binding. --- ## 2. Docker & Orchestration Configuration The production stack runs under Docker Compose using `docker-compose.prod.yml`. - [ ] Install Docker Engine v24.x or later and Docker Compose v2.x. - [ ] Ensure all containers are configured with `restart: always` or `restart: unless-stopped` policies. - [ ] Define CPU and Memory resource limits on the `gateway` and `celery_worker` containers to prevent out-of-memory cascading crashes. - [ ] Create persistent volumes for `pgdata_prod` and `mqtt_data_prod` to prevent data loss on image upgrades. - [ ] Run a test syntax build check: ```bash docker compose -f docker-compose.prod.yml config ``` --- ## 3. Environment Variables & Secrets Configuration Copy the `.env.production.template` configuration template to `.env.production` and populate the actual secrets. Do NOT use the default placeholder credentials. - [ ] Generate a secure 64-character hex string for `SECRET_KEY` (JWT signature key): ```bash openssl rand -hex 32 ``` - [ ] Set `APP_ENV=production` to disable debugging endpoints and logging details that could leak database schemas. - [ ] Configure `DATABASE_URL` with a secure, randomized password for the `pypy_admin` Postgres user. - [ ] Ensure `BILLING_PROVIDER` is set to `stripe` or `toyyibpay` depending on deployment target, and fill in the corresponding live API keys and webhook secrets. - [ ] Verify SMTP parameters: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, and `SMTP_PASSWORD` must point to a valid transaction email gateway (e.g., SendGrid, Mailgun, or AWS SES). - [ ] Provide a valid OpenAI API key (`OPENAI_API_KEY`) for AI Copilot research features. --- ## 4. NGINX Reverse Proxy & SSL Configuration Nginx terminates SSL/TLS connections and routes subdomains to internal services. - [ ] Copy `nginx/pypygrid.conf` to `/etc/nginx/sites-available/pypygrid.conf` and symlink to `sites-enabled/`. - [ ] Test the configuration: `sudo nginx -t`. - [ ] Obtain Let's Encrypt certificates using Certbot: ```bash sudo certbot --nginx -d pypygrid.com -d app.pypygrid.com -d api.pypygrid.com ``` - [ ] Verify HTTP-to-HTTPS redirect is working correctly for all endpoints. - [ ] Check security headers using an online audit tool (e.g., securityheaders.com). Ensure HSTS, CSP (Content Security Policy), X-Frame-Options, and X-Content-Type-Options are active. --- ## 5. Database Pre-seeding & Migration Prior to user signup, seed the database with required schemas and baseline scenario configurations. - [ ] Run migrations to construct database tables: ```bash docker compose -f docker-compose.prod.yml exec gateway alembic upgrade head ``` - [ ] Verify the default superuser account `admin@pypygrid.com` is seeded. Change the default password immediately on first login. - [ ] Confirm baseline IEEE grid topology templates (IEEE-14, IEEE-39, IEEE-57, IEEE-118) are imported and active in the database. --- ## 6. Pre-Launch Verification Run Run the integrated launch verification script to validate all components: - [ ] Execute the check: ```bash python3 verify_v119.py ``` - [ ] Verify the output reports `VERIFICATION RESULT: SUCCESS (All Assertions Pass)`. - [ ] Check that a backup is successfully generated and verified in `/backups`. deployment security production configuration ports firewall
