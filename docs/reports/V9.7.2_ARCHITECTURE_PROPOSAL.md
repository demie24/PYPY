### Executive Summary

The **Artificial Cyber Pathogen (PYPY V9.7.1)** established a highly adaptive, PPO-based attacker capable of executing coordinated cyber-physical sequences (FDIA, DoS, Replay, line tripping) that successfully bypassed consensus-based defense layers. 

**PYPY V9.7.2** shifts the paradigm from attack to defense by designing the **Artificial Cyber-Physical Immune System (Blue Agent)**. This document outlines the vision, biological foundations, observation/action formulations, co-evolution framework, and implementation roadmap for v9.7.2.

## 2. Blue Agent Observation & Action Spaces

The Blue Agent must act as a closed-loop controller, responding to grid anomalies in real-time.

```
       +---------------------------------------------+
       |             PHYSICAL GRID STATE             |
       +---------------------------------------------+
                        |                   ^
      Observation Vector|                   |Mitigation Action
                        v                   |
       +---------------------------------------------+
       |             BLUE PPO AGENT POLICY           |
       +---------------------------------------------+
         |                                         ^
         |Query Antigen                             |Recall Flag
         v                                         |
       +---------------------------------------------+
       |          IMMUNE MEMORY (AUTOENCODER)        |
       +---------------------------------------------+
```

### 2.1 Observation Space Design (299 Dimensions)
To make informed decisions, the Blue Agent observes both physical grid states and cyber alerts. The observation vector is structured as a flat array of 299 dimensions:

1. **Voltages (39 dims)**: Current voltage magnitudes $V$ at all 39 buses.
2. **Active Power Injections (39 dims)**: Real power $P$ injections at all 39 buses.
3. **Line Loadings (46 dims)**: Current loadings (fraction of thermal limit) for all 46 transmission lines.
4. **Breaker States (46 dims)**: Status (0 for OPEN, 1 for CLOSED) of all 46 line breakers.
5. **GNN Risk Scores (39 dims)**: Local node anomaly risk scores computed by the static GNN detector.
6. **ST-GNN Forecasted Risk (39 dims)**: Spatial-temporal forecasted risk scores.
7. **Bus Trust Scores (39 dims)**: Stateful trust scores representing the credibility of each bus's telemetry.
8. **Consensus Decisions (6 dims)**: One-hot encoded state of the global threat level ("NORMAL", "WARNING", "ANOMALY", "RECOVERY_REQUIRED", "ATTACK_CONFIRMED", "ISOLATE_COMPONENT").
9. **Immune Memory Recall Flags (6 dims)**: Output from the Immune Memory system, indicating the cosine similarity score relative to known attack categories.

### 2.2 Action Space Design (Multi-Discrete)
The Blue Agent must select *what* defense action to execute and *where* to execute it. We propose a Multi-Discrete action space `[Defense Action Type, Target Asset]`:

1. **Defense Action Type (Discrete, 7 options)**:
   * `0: NO_ACTION` - Remain idle to conserve effort and avoid operational overhead.
   * `1: ISSUE_WARNING` - Flag a target asset as suspicious; increases regional monitoring frequency.
   * `2: QUARANTINE_TELEMETRY` - Reject SCADA measurements from the target bus (substitutes state estimation defaults) to block FDIA/Replay propagation.
   * `3: ISOLATE_BUS` - Open all breakers adjacent to the target bus, containing the cyber infection.
   * `4: RECONNECT_LINE` - Close breakers on a tripped line (FLISR logic) to restore power flow.
   * `5: REROUTE_POWER` - Adjust generator active power setpoints to relieve overload on lines adjacent to the target asset.
   * `6: RESET_TRUST` - Re-authenticate bus communication channels, resetting its bus trust score to 1.0.
2. **Target Asset (Discrete, 46 options)**:
   * Index (0 to 38) maps to Buses 1 to 39.
   * Index (39 to 45) maps to tripped critical lines.

## 3. Reward Function Design

The Blue Agent's reward function ($R_{\text{Blue}}$) must incentivize physical stability, rapid cyber containment, and low operational cost, penalizing excessive actions (false alarms):

$$R_{\text{Blue}} = R_{\text{Stability}} + R_{\text{Containment}} + R_{\text{Recovery}} - C_{\text{Defense}}$$

### 3.1 Reward Components

#### A. Grid Physical Stability ($R_{\text{Stability}}$)
* **Voltage Violation Penalty**: Penalize voltage deviations outside the nominal range $[0.95, 1.05]$ pu:
  $$P_{\text{Volt}} = - \sum_{i=1}^{39} \max(0, 0.95 - V_i) - \sum_{i=1}^{39} \max(0, V_i - 1.05)$$
* **Thermal Overload Penalty**: Penalize line flows exceeding 100% capacity:
  $$P_{\text{Overload}} = - \sum_{l=1}^{46} \max(0, \text{Loading}_l - 1.0)$$
* **Load Shedding Penalty**: Severely penalize active load loss (representing blackouts):
  $$P_{\text{Shed}} = - 100.0 \times \left(1.0 - \frac{\text{Actual Load Served}}{\text{Nominal Demand}}\right)$$

#### B. Cyber Containment ($R_{\text{Containment}}$)
* **Stealth Attack Detection Bonus**: $+20.0$ when the Blue Agent successfully applies `QUARANTINE_TELEMETRY` or `ISOLATE_BUS` to a bus that is currently undergoing active FDIA/Replay/DoS.
* **Bypass Mitigation**: $+30.0$ if an active pathogen attack is successfully blocked before triggering a physical line trip.

#### C. Grid Recovery & Restoration ($R_{\text{Recovery}}$)
* **Successful FLISR Bonus**: $+15.0$ when the Blue Agent restores a tripped line (via `RECONNECT_LINE`) that does not cause subsequent thermal overloads.
* **Trust Reset Bonus**: $+5.0$ when resetting trust on a clean, secured bus.

#### D. Defense Operational Cost ($C_{\text{Defense}}$)
* **Quarantine Cost**: $-1.0$ per step a bus telemetry stream is quarantined.
* **Bus Isolation Cost**: $-15.0$ for opening adjacent breakers (operational cost of disconnection).
* **False Alarm Penalty**: $-10.0$ if the Blue Agent isolates a bus or quarantines telemetry on an asset that is not undergoing active attack.

## 4. Immune Memory Design

```
   [Telemetric Antigen (X)] -> [Encoder] -> [Latent Embedding (z)]
                                                  |
                                                  v
   [Memory Database] <---- Cosine Similarity <----+
   (Key-Value Stores)        (Threshold theta)
          |
          +---> Matching Key Found ---> Inject Recall Flags into Obs
          |
          +---> No Match Found     ---> Store new (z, antibody_action)
```

To emulate memory B/T cells, PYPY V9.7.2 will implement a **Latent Memory Store**:

### 4.1 Embedding Antigen Signatures
1. We train a lightweight **Variational Autoencoder (VAE)** on nominal and anomalous grid state sequences.
2. At each timestep, the telemetry deviation vector $X = [V - V_{\text{nominal}}, P - P_{\text{nominal}}, \text{Loading}]$ is projected into a 16-dimensional latent space $z = \text{Encoder}(X)$.
3. This latent vector $z$ serves as the **Antigen Signature**.

### 4.2 Key-Value Memory Database
* The Blue Agent maintains a memory database of key-value pairs:
  $$\mathcal{M} = \{(z_k, a_k)\}_{k=1}^K$$
  where $z_k$ is the historical antigen signature and $a_k$ is the successful mitigation action.
* **Querying (Recall)**: During an episode, the active antigen $z$ is compared against all stored keys using cosine similarity:
  $$S_k = \frac{z \cdot z_k}{\|z\| \|z_k\|}$$
* **Thresholding**: If $\max_k S_k > \theta$ (e.g., $\theta = 0.85$), the immune system triggers a **Recall Event**:
  * The index of the matching memory category is set in the `Immune Memory Recall Flags` observation.
  * The Blue Agent policy can bypass exploration and immediately execute the associated mitigation action $a_k$.
* **Consolidation**: If an attack is successfully mitigated (episode ends with positive reward) but has no matching memory, the new pair $(z, a_{\text{successful}})$ is saved into $\mathcal{M}$.

## 5. Adversarial Co-Evolution Strategy

To ensure both agents achieve publication-quality robustness, they must be trained against one another in a competitive self-play league.

```
                  +-----------------------------------+
                  |        Active Pathogen (Red)      |
                  +-----------------------------------+
                                    |
                                    v (Attacks)
  +-------------+       +-----------------------+       +-------------+
  |  Pathogen   | <---> |  Grid Env Simulator   | <---> |   Immune    |
  | League Pool |       +-----------------------+       | League Pool |
  +-------------+                   ^                   +-------------+
                                    | (Mitigations)
                  +-----------------------------------+
                  |        Active Immune (Blue)       |
                  +-----------------------------------+
```

### 5.1 Training Framework: League Self-Play
We reject simple alternating PPO training because it is prone to **policy cycling** (Red learns to defeat Blue; Blue adapts to defeat Red, but both forget earlier strategies). Instead, we propose a **League Self-Play** framework:

1. **Checkpoints Pools**: Maintain historical checkpoint pools for the Pathogen ($\mathcal{H}_{\text{Red}}$) and the Immune System ($\mathcal{H}_{\text{Blue}}$).
2. **Adversarial Matchmaking**: At the start of each training episode, the active agent is matched against a mix of opponents:
   * **80% Probability**: A historical opponent sampled from the opponent league pool (forcing generalization).
   * **20% Probability**: The latest active version of the opponent (forcing adaptation to current exploits).
3. **Alternating Training Epochs**:
   * **Epoch $2N$**: Freeze Blue Agent weights. Train Red Agent against the league of Blue policies.
   * **Epoch $2N+1$**: Freeze Red Agent weights. Train Blue Agent against the league of Red policies.

### 5.2 Curriculum Learning
To stabilize early co-evolution, we establish a 3-stage curriculum:
* **Stage 1 (Innate Priming)**: Blue Agent is trained against a static, rule-based attacker. Red Agent is trained against the rule-based consensus defense.
* **Stage 2 (Adaptive Co-Evolution)**: Red and Blue agents train directly against each other, but the actions available to Red are restricted to simple line trips and FDIA.
* **Stage 3 (Full Cyber-Physical Warfare)**: All actions are enabled for both agents. The agents train via league self-play on various grid load fluctuation scenarios (scenario diversity).

## 7. Risks, Challenges, and Mitigations

| Identified Risk | Impact | Mitigation Strategy |
| :--- | :--- | :--- |
| **Co-Evolution Divergence** | Policy collapse or unstable learning curves. | Utilize a high entropy coefficient in PPO training to encourage exploration and enforce gradient clipping. |
| **Defensive Action Chattering** | Agent repeatedly opens/closes breakers, causing grid collapse. | Add a high negative penalty for action transitions (breaker state switches) and operational costs. |
| **State Estimation Mismatches** | Quarantined telemetry causes AC solver non-convergence. | Ensure the grid physics engine automatically falls back to last-known nominal states for quarantined buses. |
| **Out-of-Distribution Antigens** | Immune memory fails to generalize to new attack patterns. | Apply a threshold margin ($\theta = 0.85$) for memory recall; if similarity is low, fallback to active PPO policy exploration. |
